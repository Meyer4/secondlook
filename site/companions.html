A QUIETER KIND OF TOOLKIT

Only work when
there’s something to check.

Lightweight, English-first rules. No continuous polling, cloud AI, or browsing-history collection.

01

Permission first.

Android apps are unselected and protection is paused on a fresh install. Browser access is opt-in. Revoke access whenever you choose.

02

Less noise.

Android uses a bounded queue and in-memory deduplication. Repeat warnings are limited. Your OS can still suppress notifications.

03

No battery promises.

Visual motion runs only while the interface is visible and can be disabled. Notification checking remains event-driven. Physical-phone battery drain, OEM reliability, and real messaging-app coverage still need device testing.

SET IT UP, ON YOUR TERMS

Start with your device.

Download checksums ↗
01 Android: install and choose what to check +
  1. Download the preview APK. It is non-debuggable but preview-signed, not store-reviewed. Review the source and permissions before installing it on your own device. Do not disable Play Protect or OTP redaction.
  2. Open SecondLook. Allow it to show warning notifications if you want alerts.
  3. Read the explanation, then open Android’s Notification access settings and enable SecondLook only if you accept that powerful permission.
  4. Select the messaging apps you want checked, apply your choices, and turn on local notification checks. No apps are selected by default.
  5. Return to SecondLook and check its connection/permission status. Try a fictional test message from a separate device. Actual app notifications must contain readable text.

Important: Android may restrict sideloaded listeners, work-profile notifications, sensitive content, or background activity. The app does not work around those controls. A connected status is not a guarantee that every notification will be scanned. Version 1.3 installs as SecondLook from a separate package, so it can be installed alongside the earlier 1.1 app. Configure its permissions and app choices again, then pause or remove the older installation to avoid duplicate alerts. If you installed an earlier 1.2 preview and Android reports a signature conflict, remove that preview before installing this one. Future production updates require an owner-controlled signing key.

For a link already inside another app, use that app’s Share → SecondLook action if available. Installing this APK does not turn SecondLook into a universal link interceptor.

02 Chrome / Edge: load the unpacked extension +
  1. Download and extract the browser extension ZIP on your computer.
  2. Open chrome://extensions or edge://extensions. Turn on Developer mode.
  3. Choose Load unpacked, then select the extracted folder that contains manifest.json. This is a development installation, not a store-verified extension.
  4. Open SecondLook’s extension controls. Grant access to a website or all web sites, and enable Link Guard. Read your browser’s consent prompt.
  5. Reload other open websites. Choose a warning threshold and, optionally, permit browser notifications.

The browser’s own site-access settings can further restrict access. Restricted pages and certain navigations cannot be covered. The extension does not read all chat messages. Chrome on Android and iPhone does not use this desktop installation workflow.

03 iPhone: build, sign, and enable the extensions +
  1. Download the iPhone project ZIP. It contains Swift source, a Share extension, Safari extension resources, native tests, and an XcodeGen project specification.
  2. On a Mac with Xcode, install XcodeGen and run xcodegen generate inside the extracted project. Open SecondLook.xcodeproj.
  3. Choose an Apple development team and suitable bundle identifiers for the app and both extensions. Use Xcode’s signing workflow to install on your own iPhone. A simulator build cannot be installed on a phone.
  4. To use the Share extension, share text or a URL and select Check with SecondLook. Some apps do not expose their message text.
  5. For Safari, enable SecondLook in Safari’s extension settings, grant website permissions, and turn on Link Guard in its controls.

Public App Store / TestFlight distribution requires Apple’s developer-account, signing, privacy-disclosure, and review processes. That publication is not included or claimed here. Real iPhone/Safari permission behavior still needs device testing.

!

More convenient does not mean all-knowing.

These companions recognise defined warning patterns, not every scam. Legitimate content can trigger a warning. No warning is not a “safe” verdict. Links, files, senders, and live website reputations are not verified. Keep using independent verification for unexpected money or account requests.
